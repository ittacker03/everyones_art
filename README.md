# 모두의 아트 (Everyone's Art)

사용자가 직접 그림을 그리고, 블록으로 전시 공간을 꾸민 뒤 다른 사용자와
작품을 공유하는 웹 기반 가상 전시 서비스입니다.

## 1. 프로젝트 개요

### 주요 기능

-   회원가입 및 로그인
-   작품 제작 및 관리
-   블록 디자인 제작 및 관리
-   블록을 배치해 전시 공간 꾸미기
-   작품을 액자에 넣어 전시하기
-   다른 사용자의 전시 공간 관람
-   좋아요 및 방명록

### 기술 스택 및 데이터 저장

-   서버: Node.js, Express
-   데이터베이스: 별도 DB를 사용하지 않고 JSON 및 텍스트 파일로 저장
-   이미지 파일: 별도 파일로 저장
-   로그인 세션: `express-session` 사용
-   세션 저장소: 기본 메모리 저장소 사용을 전제로 함

브라우저를 다시 실행한 뒤 로그인 상태가 유지될 필요는 없습니다. 서버가
재시작되면 메모리 저장소의 세션도 초기화됩니다.

## 2. 페이지 구성

  페이지             기능
  ------------------ ----------------------------------
  `main`             메인 화면 및 공개 전시 공간 목록
  `gallery_list`     전시 공간 목록 및 정렬
  `gallery_user`     특정 사용자의 전시 공간 목록
  `gallery_create`   전시 공간 생성
  `gallery_edit`     전시 공간 편집 전용 페이지
  `item_create`      작품 제작 및 등록
  `mypage`           사용자 정보 및 개인 콘텐츠 관리
  `sign_in`          회원가입 및 로그인

실제 URL과 파일명은 현재 프로젝트의 라우팅 및 뷰 구조에 맞춥니다. `gallery_edit`은 메인 페이지와 분리된 독립 HTML 페이지입니다.

## 3. 회원 및 로그인

### 회원가입

-   아이디: 2\~20자
-   허용 문자: 한글, 영문, 숫자, 밑줄(`_`)
-   비밀번호: 4자 이상
-   비밀번호는 해시 처리하여 저장합니다.
-   회원가입 시 비밀번호 확인 입력란을 제공하며, 두 값이 일치해야 가입할 수 있습니다.
-   비밀번호가 일치하지 않으면 비밀번호 확인 입력란 아래에 `비밀번호가 일치하지 않습니다.`를 표시합니다.
-   아이디 형식이 올바르지 않으면 아이디 입력란 아래에 `아이디는 2~20자의 한글, 영문, 숫자, 밑줄만 사용할 수 있습니다.`를 표시합니다.
-   이미 사용 중인 아이디를 입력하면 아이디 입력란 아래에 중복 오류 메시지를 표시합니다.
-   비밀번호가 4자 미만이면 비밀번호 입력란 아래에 `비밀번호는 4자 이상이어야 합니다.`를 표시합니다.
-   별도 닉네임은 입력받지 않으며 아이디를 사용자 표시 이름으로 사용합니다.
-   가입 후 아이디 변경, 비밀번호 변경, 비밀번호 재설정 및 회원 탈퇴 기능은 제공하지 않습니다.

### 로그인

-   Express Session을 사용합니다.
-   아이디 또는 비밀번호가 틀리면 로그인 버튼 아래에 `아이디 또는 비밀번호가 올바르지 않습니다.`를 표시합니다.
-   로그인 성공 후에는 항상 메인 페이지로 이동합니다.
-   이미 로그인한 사용자가 로그인 페이지에 접근하면 안내 없이 메인 페이지로 이동합니다.
-   로그아웃은 별도 확인 없이 즉시 처리하고 메인 페이지로 이동합니다.
-   브라우저를 종료한 뒤 다시 접속했을 때 로그인 상태가 유지되지 않아도
    됩니다.
-   서버 재시작 시 기존 세션은 초기화됩니다.


## 3-1. 마이페이지 및 페이지 접근 권한

### 마이페이지

-   마이페이지에는 아이디, 가입일, 내가 만든 전시 공간 수, 내가 만든 작품 수를 표시합니다.
-   마이페이지에서 내 전시 공간 목록을 확인하고 각 전시 공간의 이름, 소개, 대표 이미지를 수정하거나 삭제할 수 있습니다.
-   마이페이지에서 내 작품 목록을 확인하고 각 작품의 제목, 설명, 그림을 수정하거나 삭제할 수 있습니다.
-   블록 디자인 관리는 마이페이지에 포함하지 않습니다.

### 상단 메뉴 및 관리 페이지 접근

-   상단 메뉴에는 `홈`, `전시 공간`, `마이페이지`, `로그인/로그아웃`을 표시합니다.
-   작품 관리 페이지는 마이페이지의 `내 작품 관리` 링크를 통해 접근합니다.
-   블록 디자인 관리 페이지는 별도 페이지로 제공하지만, 상단 메뉴에는 포함하지 않습니다. 페이지 진입 경로는 아직 결정하지 않았습니다.
-   작품 관리 및 블록 디자인 관리 페이지는 로그인한 사용자만 접근할 수 있습니다.
-   비로그인 사용자가 마이페이지, 전시 공간 생성, 작품 관리, 블록 디자인 관리 페이지에 접근하면 로그인 페이지로 이동시킵니다.
-   비로그인 사용자가 전시 공간 만들기 또는 작품 만들기 기능을 실행해도 로그인 페이지로 이동시킵니다.
-   로그인 후에는 원래 접근하려던 페이지로 돌아가지 않고 항상 메인 페이지로 이동합니다.
-   비로그인 사용자가 좋아요 버튼을 누르면 로그인 페이지로 이동시킵니다.
-   비로그인 사용자가 좋아요 또는 방명록 작성 기능을 이용하려 하면 로그인 페이지로 이동시킵니다.

## 4. 전시 공간

### 생성 및 공개

-   사용자 한 명이 생성할 수 있는 전시 공간은 최대 5개입니다.
-   전시 공간 생성 시 사용자가 이름을 직접 입력해야 합니다.
-   전시 공간 이름은 생성 후에도 수정할 수 있습니다.
-   소개 글은 선택 사항이며 최대 100자입니다.
-   모든 전시 공간은 기본적으로 공개 상태입니다.
-   전시 공간별 비공개 설정은 제공하지 않습니다.

### 대표 이미지

-   대표 이미지 업로드는 선택 사항입니다.
-   업로드하지 않으면 기본 이미지를 표시합니다.
-   허용 형식: PNG, JPG
-   최대 파일 크기: 5MB
-   업로드한 이미지는 나중에 변경할 수 있습니다.
-   목록에 표시할 때 원본 비율을 유지하면서 정해진 영역에 맞춰
    축소합니다. 이미지가 잘리지 않으며 남는 공간에는 여백이 생길 수
    있습니다.

### 전시 공간 크기

-   바닥은 처음부터 전체가 존재하는 고정된 20×20칸입니다.
-   사용자는 바닥 타일을 설치하거나 삭제할 수 없습니다.
-   전시 공간은 최대 3층까지 사용할 수 있습니다.
-   블록은 공중에 떠 있는 형태로도 설치할 수 있습니다.
-   별도의 전체 블록 개수 제한은 현재 정하지 않았습니다.

### 전시 공간 삭제

-   소유자만 자신의 전시 공간을 삭제할 수 있습니다.
-   삭제 전 확인 창을 표시합니다.
-   삭제를 확인하면 전시 공간을 즉시 삭제합니다.
-   해당 전시 공간의 블록, 액자, 방명록, 좋아요 정보도 함께 삭제합니다.
-   작품 원본 파일과 블록 디자인은 삭제하지 않습니다.

## 5. 블록 및 전시 공간 편집

### 블록 형태와 시점

-   블록 크기: 1×1×1
-   전시 공간은 20×20 바닥과 최대 3개 층으로 구성합니다.
-   아이소메트릭 형태로 표현하고 카메라 시점은 고정합니다.
-   카메라 이동·확대·축소·회전은 지원하지 않습니다.
-   20×20 바닥 전체가 화면에 보이도록 구성합니다. 반응형 축소 방식은
    구현 전 현재 화면 구조를 확인해 정합니다.
-   바닥 타일은 설치하거나 삭제할 수 없으며 공중 위치에도 블록을 설치할 수
    있습니다. 블록 수에 별도 총량 제한을 두지 않습니다.

### 블록 디자인

-   기본 블록은 회색입니다.
-   사용자는 블록 디자인을 직접 제작할 수 있습니다.
-   하나의 블록 디자인은 여러 블록에서 재사용할 수 있습니다.
-   블록 디자인은 사용자별로 독립적으로 관리하며 다른 사용자의 디자인은
    선택하거나 사용할 수 없습니다.
-   사용자는 자신의 디자인을 자신이 소유한 전시 공간에서 재사용할 수
    있습니다.
-   사용자당 블록 디자인 생성 개수에는 제한이 없고 복사 기능은 제공하지
    않습니다.
-   디자인 목록은 최신 생성순으로 표시하고 아이소메트릭 미리보기를
    제공합니다.

### 블록 디자인 편집 방식

-   앞면·옆면·윗면 각각에 독립적인 32×32 도트 캔버스를 제공합니다.
-   앞면은 정사각형, 옆면과 윗면은 아이소메트릭 블록 면에 맞춘
    평행사변형으로 표시합니다. 원근 변환이 아니라 도트 단위로 면에
    매핑합니다.
-   캔버스와 아이소메트릭 블록 미리보기를 함께 표시하고 편집할 면을
    선택할 수 있습니다.
-   작품 제작과 같은 펜·지우개·채우기·전체 지우기 도구를 사용합니다.
-   디자인 이름은 필수이며 최대 20자입니다. 생성 후 수정할 수 있고,
    같은 사용자의 디자인 이름은 중복될 수 없습니다.
-   편집 중인 내용은 저장 버튼을 누르기 전까지 미리보기에 반영하지
    않습니다. 저장하지 않고 나가면 변경 내용을 버리고 기존 디자인을
    유지합니다.
-   디자인을 수정해 저장하면 해당 디자인을 참조하는 기존 블록에도 수정된
    디자인 이미지가 반영됩니다. 디자인 목록에서 새 디자인을 골라 블록을
    설치할 때의 적용 규칙은 아래와 같이 별도로 정합니다.

### 블록 디자인과 설치된 블록의 관계

-   블록은 디자인 ID(`designId`)를 참조합니다.
-   편집 화면 한쪽에 현재 사용자가 만든 디자인 목록을 표시하고 마우스로
    선택할 수 있습니다. 목록에는 `기본 회색` 항목도 둡니다.
-   선택한 디자인은 이후 새로 설치하는 블록에만 적용합니다. 이미 설치된
    블록의 디자인은 선택만으로 바뀌지 않습니다.
-   디자인을 선택하지 않았거나 `기본 회색`을 선택하면 이후 설치할 블록은
    회색입니다.
-   디자인 편집 및 저장은 디자인 ID를 참조하는 기존 블록에 적용됩니다.
-   디자인 삭제 전 확인 창을 표시합니다. 삭제하면 그 디자인을 사용하던
    블록은 기본 회색으로 바뀌지만 위치와 액자는 유지합니다.

### 블록 설치 및 제거 조작

-   편집기는 `index.html`에 삽입하지 않고 `gallery_edit` 독립 페이지로
    제공합니다. 기존 로그인 및 소유권 접근 제어를 적용합니다.
-   `블록 설치`, `블록 제거`, `액자 설치`, `액자 제거`를 각각 별도 버튼으로
    전환합니다. 현재 모드를 항상 구분해 표시합니다.
-   편집 위치는 마우스로 격자를 클릭해 정하지 않습니다. 방향키로 한 칸씩
    이동하고, 아이소메트릭 화면에 보이는 방향을 기준으로 합니다.

  키    화면상 이동 방향
  ----- ------------------
  `↑`   왼쪽 위
  `→`   오른쪽 위
  `↓`   오른쪽 아래
  `←`   왼쪽 아래

-   방향키 이동은 20×20 바닥 범위 안에서만 허용합니다. 가장자리에서 바깥
    방향으로 이동을 시도하면 멈추며 반대편으로 순환하지 않습니다.
-   처음 열었을 때 선택 위치는 중앙 네 칸 중 화면 기준 왼쪽 위 칸입니다.
-   층 선택기에 `1층`, `2층`, `3층`을 제공합니다. 층을 바꿔도 `(x, y)`를
    유지하고 `z`만 바꿉니다. 해당 칸이 다른 층에서 점유되어 있어도 선택
    위치를 자동 이동하지 않으며 그 위치에는 설치할 수 없습니다.
-   선택 칸은 테두리 또는 반투명 오버레이로 표시하고, 겹친 블록보다 위에
    그려 가려지지 않게 합니다. 설치 모드와 제거 모드는 다른 시각 스타일로
    구분합니다.
-   설치 모드에서 빈 위치를 선택한 뒤 `Enter`를 누르면 블록을 설치합니다.
  이미 점유된 위치에는 설치하지 않습니다. 설치 후 선택 위치를 유지합니다.
-   제거 모드에서 `Enter`를 누르면 현재 칸의 블록을 제거합니다. 빈 칸에는
    아무 작업도 하지 않습니다. 블록을 제거하면 해당 블록의 액자도 함께
    제거하지만 작품 원본은 삭제하지 않습니다.
-   층이나 모드를 바꾸거나 액자를 제거해도 선택 좌표를 유지합니다.
-   편집 조작 중 방향키가 페이지를 스크롤하지 않게 합니다. 텍스트 입력
    요소에 포커스가 있을 때는 방향키 입력을 가로채지 않습니다.

### 편집 변경 저장 및 페이지 이탈

-   블록·액자 변경은 자동 저장하지 않습니다. 저장 버튼을 눌렀을 때 저장합니다.
-   저장 중에는 저장 버튼을 비활성화합니다. 성공하면 `저장 완료`를 3초간
    표시한 뒤 자동으로 숨깁니다.
-   실패하면 오류 안내와 `다시 저장` 버튼을 표시하고 편집 변경 내용을
    유지합니다. 사용자가 방향키로 선택 위치를 움직여 편집을 다시 시작하면
    오류 안내와 재시도 버튼을 숨기지만 변경 내용은 그대로 남기고 일반
    저장 버튼을 계속 사용할 수 있게 합니다.
-   저장하지 않은 변경 사항이 있는 상태에서 페이지를 나가려 하면
    `저장하고 나가기`, `저장하지 않고 나가기`, `계속 편집`을 제공합니다.
    기본 선택은 `계속 편집`입니다.

## 6. 작품 및 액자

### 작품 제작

-   작품 캔버스 크기: 512×512픽셀
-   저장 형식: PNG
-   작품 이미지 파일 용량 제한은 두지 않습니다.
-   사용자당 작품 생성 개수 제한은 없습니다.
-   작품 생성, 수정, 삭제를 지원합니다.
-   작품 제목은 필수이며 최대 20자입니다.
-   작품 설명은 선택 사항이며 최대 100자입니다.
-   작품 제목과 설명은 등록 후에도 수정할 수 있습니다.
-   같은 사용자의 작품끼리는 제목이 중복될 수 없습니다. 생성 및 제목 수정 시 중복을 검사합니다.
-   작품 복사 기능은 제공하지 않습니다.
-   작품 목록은 최신 생성순으로 표시합니다.
-   작품 수정 화면에는 기존 그림을 불러와 이어서 수정할 수 있도록 합니다.
-   수정 내용을 저장하지 않고 나가면 변경 내용을 버리고 기존 작품을 유지합니다.
-   펜, 지우개, 채우기, 전체 지우기 도구를 제공합니다.

### 액자 설치

-   편집 화면 한쪽에 현재 사용자의 작품 목록을 표시하고, 마우스로 전시할
    작품을 선택합니다.
-   작품을 선택한 뒤 `액자 설치` 모드로 전환하고 방향키로 블록 위치를
    선택합니다. `Enter`를 누르면 액자를 설치합니다.
-   액자는 블록 앞면에만 설치할 수 있습니다. 옆면과 윗면에는 설치할 수
    없습니다.
-   블록 앞면 하나에는 액자 하나만 설치합니다. 이미 액자가 있는 블록에는
    새 액자를 설치하지 않고, 먼저 기존 액자를 제거해야 합니다.
-   액자는 블록 앞면의 정중앙에 고정되며 크기는 앞면 가로·세로 각각
    80%입니다. 이동하거나 크기를 조절할 수 없습니다.
-   액자 내부에는 작품 이미지만 표시하고 제목은 표시하지 않습니다.
    이미지는 원본 비율을 유지해 액자 안에 맞춥니다.
-   액자 설치에 성공하면 액자 설치 모드를 종료하고 선택 작품을 해제합니다.

### 액자 제거 및 작품 연결

-   `액자 제거` 모드에서 방향키로 위치를 선택하고 `Enter`를 누릅니다.
-   액자를 제거하면 전시 공간의 액자와 작품 연결만 해제합니다. 작품 파일과
    작품 정보는 보존합니다.
-   액자가 없는 블록에서 제거를 확정하면 `제거할 액자가 없습니다` 안내를
    표시합니다.
-   액자 제거 후에도 선택 위치를 유지합니다. 액자를 다시 설치하려면 작품을
    선택하고 설치 모드로 전환합니다.
-   액자를 제거하지 않고 작품을 바로 교체하는 기능은 제공하지 않습니다.

### 작품 삭제와 빈 액자

-   작품 삭제 전 확인 창을 표시합니다.
-   작품을 삭제해도 해당 액자는 제거하지 않고 `빈 액자` 상태로 남깁니다.
    작품 삭제는 작품 파일과 정보를 삭제하는 작업이며, 액자 제거와 다릅니다.
-   빈 액자에는 새 작품을 연결할 수 있습니다.
-   작품 원본을 삭제해도 다른 작품이나 블록 위치에는 영향을 주지 않습니다.

## 7. 방문자 기능: 좋아요 및 방명록

### 공개 관람 및 비로그인 권한

-   공개된 전시 공간은 누구나 관람할 수 있습니다.
-   비로그인 사용자는 관람만 가능합니다.
-   좋아요와 방명록 작성은 로그인한 사용자만 이용할 수 있습니다.
-   비로그인 사용자가 좋아요 또는 방명록 작성 기능을 이용하려 하면 로그인 페이지로 이동시킵니다.

### 좋아요

-   로그인한 사용자는 전시 공간에 좋아요를 누르거나 취소할 수 있습니다.
-   사용자 한 명은 전시 공간 하나에 좋아요를 한 번만 누를 수 있습니다.
-   같은 버튼을 다시 누르면 좋아요가 취소됩니다.
-   전시 공간에는 좋아요 개수만 표시합니다.
-   좋아요를 누른 사용자 목록은 공개하지 않습니다.
-   전시 공간 소유자도 자신의 전시 공간에 좋아요를 누르거나 취소할 수 있습니다.

### 방명록

-   로그인한 사용자만 방명록을 작성할 수 있습니다.
-   방명록 한 개의 최대 글자 수는 100자입니다.
-   최신 작성순으로 표시합니다.
-   한 페이지에 최대 10개를 표시하며, 그보다 많으면 페이지를 나눕니다.
-   작성자는 본인이 작성한 방명록을 수정하거나 삭제할 수 있습니다.
-   다른 사용자의 방명록은 수정하거나 삭제할 수 없습니다.
-   방명록 수정 시 최대 100자 제한을 다시 적용합니다.
-   수정된 방명록은 기존 작성 시간을 유지합니다.
-   방명록을 수정해도 `수정됨` 표시를 추가하지 않습니다. 원래 작성 날짜만 표시합니다.
-   방명록에는 작성자 아이디와 작성 날짜만 표시하며, 작성 시간은 표시하지 않습니다.
-   방명록에는 좋아요 기능을 제공하지 않습니다.
-   방명록은 작성자 본인만 삭제할 수 있습니다. 전시 공간 소유자라도 다른 사용자의 방명록을 삭제할 수 없습니다.
-   방명록 삭제 버튼을 누르면 확인 창을 표시합니다. 확인하면 삭제하고, 취소하면 삭제하지 않습니다.
-   방명록 작성 중 취소하면 입력한 내용을 모두 지우고 작성창을 닫습니다. 다시 작성창을 열면 빈 입력란을 표시합니다.
-   방명록 페이지에는 페이지 번호와 `이전 페이지`, `다음 페이지` 버튼을 모두 표시합니다.
-   첫 페이지에서는 `이전 페이지`, 마지막 페이지에서는 `다음 페이지` 버튼을 비활성화합니다.

## 8. 전시 공간 목록 및 정렬

전시 공간 목록에서 다음 세 가지 정렬 방식을 제공합니다.

1.  최신 등록순
2.  좋아요순
3.  오래된순

좋아요순에서 좋아요 개수가 같은 전시 공간은 최신 등록순으로 표시합니다.

## 9. 데이터 저장 방향

-   데이터베이스 대신 JSON 및 텍스트 파일을 사용합니다.
-   사용자별 전시 공간과 작품 정보를 분리해 저장합니다.
-   이미지 파일은 JSON 데이터와 별도로 저장합니다.
-   블록은 블록 디자인의 ID를 참조합니다.
-   블록 디자인을 별도 데이터로 관리하여 여러 블록에서 재사용할 수
    있도록 합니다.
-   작품 원본과 액자에 연결된 작품의 관계를 분리해 관리합니다. 작품 삭제
    시 액자는 남고 빈 액자로 바뀌어야 합니다.

구체적인 JSON 파일 구조, 파일명, 디렉터리 구조는 구현 과정에서
확정합니다.

## 10. 아직 결정하지 않은 사항

다음 항목은 구현 전에 현재 코드와 화면 구조를 확인하거나 사용자와 추가로 정합니다.

-   아이소메트릭에서 액자의 `앞면`으로 간주할 면과, 다른 블록에 가려진 면의 설치 가능 여부
-   작은 화면에서 고정 카메라와 20×20 전체 표시를 함께 만족시키는 구체적인 반응형 축소 방식
-   기존 코드에 맞는 정확한 JSON 파일 구조, API 경로 및 편집 저장 단위
-   여러 파일을 함께 저장할 때의 오류 복구와 저장 요청의 부분 반영 처리
-   저장하고 나가기 도중 저장이 실패했을 때 페이지 이탈 처리와 안내
-   블록 디자인 관리 페이지의 구체적인 진입 경로
-   색상·간격 등 세부 UI 표현
-   로그인/회원가입 및 콘텐츠 검증에서 본문에 정하지 않은 기술 세부 사항

편집 조작 키, 경계 이동, 초기 선택 위치, 디자인/작품 목록 범위, 저장 시점과
실패 피드백 등 사용자와 이미 확정한 내용은 미결정 사항으로 취급하지 않습니다.

## 11. 추가로 확정된 세부 사항

### 회원 및 접근 권한 보완

-   로그인하지 않은 사용자가 좋아요를 누르거나 방명록 작성을 시도하면 로그인 페이지로 이동합니다.
-   로그인 후에는 원래 요청한 페이지로 돌아가지 않고 항상 메인 페이지로 이동합니다.
-   작품 관리 페이지에서는 로그인한 사용자가 자신의 작품만 확인하고 관리할 수 있습니다. 다른 사용자의 작품은 이 페이지에서 확인하거나 관리할 수 없습니다.
-   블록 디자인 관리 페이지에서는 로그인한 사용자가 자신의 블록 디자인만 확인하고 관리할 수 있습니다. 다른 사용자의 디자인은 확인하거나 사용할 수 없습니다.
-   블록 디자인 관리 페이지의 구체적인 진입 경로는 아직 결정하지 않았습니다.

### 작품 관리 보완

-   마이페이지의 `내 작품 관리` 링크를 통해 작품 관리 페이지에 접근합니다.
-   작품 관리 페이지에서는 자신의 작품만 목록에 표시합니다.
-   작품 제목과 설명뿐 아니라 그림 이미지도 수정할 수 있습니다.
-   작품 목록은 최신 생성순으로 표시하며, 제목을 수정해도 목록 순서는 바뀌지 않습니다.
-   작품을 수정할 때 기존 그림을 불러와 이어서 그릴 수 있으며, 저장하면 기존 작품을 갱신합니다.
-   수정 내용을 저장하지 않고 나가면 변경 내용을 버리고 기존 작품을 유지합니다.
-   작품 삭제 시 확인 창을 표시합니다. 삭제를 확인하면 작품과 원본 이미지 파일을 삭제합니다.
-   작품이 연결되어 있던 액자는 삭제하지 않고 `빈 액자` 상태로 남깁니다.

### 블록 디자인 관리 보완

-   블록 디자인 이름은 같은 사용자의 디자인끼리 중복될 수 없습니다. 새로 만들거나 이름을 수정할 때 중복을 검사합니다.
-   디자인 이름을 수정하거나 디자인 내용을 편집해도 최초 생성 순서는 바뀌지 않습니다.
-   블록 디자인 목록은 최신 생성순으로 표시합니다.
-   디자인 편집 중 저장하지 않고 나가면 편집 내용을 버리고 기존 디자인을 유지합니다.
-   디자인 저장은 저장 버튼을 누르는 즉시 처리하며, 별도의 확인 창은 표시하지 않습니다.
-   미리보기는 저장 버튼을 눌렀을 때만 갱신합니다. 저장하지 않은 편집 내용은 미리보기에 반영하지 않습니다.
-   디자인 삭제 시 확인 창을 표시합니다. 삭제하면 해당 디자인을 사용하던 블록은 기본 회색 블록으로 바뀌지만, 블록의 위치와 설치된 액자는 유지합니다.

### 블록 설치 및 편집 보완

최신 조작 규칙은 **5. 블록 및 전시 공간 편집**을 기준으로 합니다. 이 절은 이전 문구를 반복하지 않습니다. 특히 마우스로 블록 위치를 지정하는 규칙과 설치된 블록 디자인을 목록 선택만으로 바꾸는 규칙은 적용하지 않습니다.

### 작품 및 액자 보완

최신 액자 조작과 원본 보존 규칙은 **6. 작품 및 액자**를 기준으로 합니다. 액자 설치/제거는 클릭이 아닌 별도 모드와 방향키 위치 선택, `Enter` 확정으로 진행합니다. 기존 액자에 새 작품을 바로 교체하는 기능은 제공하지 않습니다.

### 전시 공간 관람 및 좋아요 보완

-   공개된 전시 공간은 로그인 여부와 관계없이 누구나 관람할 수 있습니다.
-   로그인한 사용자는 전시 공간에 좋아요를 누르거나 취소할 수 있습니다.
-   전시 공간 소유자도 자신의 전시 공간에 좋아요를 누를 수 있습니다.
-   좋아요를 누른 사용자 목록은 공개하지 않고 좋아요 개수만 표시합니다.

### 방명록 보완

-   방명록은 로그인한 사용자만 작성할 수 있습니다.
-   방명록 한 개의 최대 글자 수는 100자입니다.
-   최신 작성순으로 표시하며 한 페이지에 최대 10개를 표시합니다.
-   방명록 작성자는 본인이 작성한 글만 수정하거나 삭제할 수 있습니다.
-   방명록 수정 시 원래 작성 날짜를 유지하며 `수정됨` 표시를 추가하지 않습니다.
-   방명록에는 작성자 아이디와 작성 날짜만 표시하고 작성 시간은 표시하지 않습니다.
-   방명록에는 좋아요 기능을 제공하지 않습니다.
-   방명록 작성 중 취소하면 입력한 내용을 지우고 작성창을 닫습니다.
-   방명록 삭제 전 확인 창을 표시합니다. 확인하면 삭제하고 취소하면 삭제하지 않습니다.
-   방명록 페이지 이동에는 페이지 번호와 `이전 페이지`, `다음 페이지` 버튼을 모두 제공합니다.
-   첫 페이지에서는 이전 페이지 버튼을, 마지막 페이지에서는 다음 페이지 버튼을 비활성화합니다.

## 12. 아직 결정하지 않은 사항

다음 항목은 구현 전에 기존 코드와 화면 구조를 확인하거나 사용자와 추가로 정합니다.

-   아이소메트릭에서 액자의 `앞면`으로 간주할 면과 다른 블록에 가려진 면의 설치 가능 여부
-   작은 화면에서 20×20 바닥 전체를 보여주는 반응형 축소 방식
-   기존 프로젝트와 일치하는 JSON 파일 구조, API 경로 및 블록·액자 저장 단위
-   여러 파일을 함께 저장할 때의 오류 복구 및 부분 저장 처리
-   저장하고 나가기 도중 저장이 실패했을 때 페이지 이탈 처리와 안내
-   블록 디자인 관리 페이지의 구체적인 진입 경로
-   세부 UI 배치, 색상 및 입력 검증 중 아직 정하지 않은 기술 사항

편집 키, 경계 이동, 초기 선택 위치, 디자인/작품 목록 범위, 저장 시점과
실패 피드백 등 사용자와 이미 확정한 내용은 미결정 사항이 아닙니다.

### 방명록 UI 및 페이지 이동 세부 규칙 (추가 결정)

-   방명록이 하나도 없을 때는 별도의 안내 문구를 표시하지 않고 빈 목록으로 둡니다.
-   방명록 작성창은 처음부터 표시하지 않습니다. `방명록 작성` 버튼을 눌렀을 때만 엽니다.
-   방명록 작성창은 방명록 목록 아래에 표시합니다.
-   방명록 작성 중 취소하면 입력 내용을 모두 지우고 작성창을 닫습니다.
-   방명록 작성 입력창 아래에 `현재 글자 수 / 100자`를 실시간으로 표시합니다.
-   방명록 수정 입력창에도 `현재 글자 수 / 100자`를 실시간으로 표시하며, 100자를 초과해 입력할 수 없습니다.
-   방명록 수정은 목록 안에서 기존 내용이 입력창으로 바뀌는 방식으로 진행합니다.
-   수정 중 취소하면 수정 전 내용으로 되돌리고 입력창을 닫습니다.
-   수정을 완료하면 수정된 내용을 저장하고 수정 입력창을 닫습니다.
-   방명록을 수정해도 최초 작성 날짜와 목록 순서를 유지합니다. `수정됨` 표시는 하지 않습니다.
-   방명록 등록을 완료하면 작성창을 닫습니다. 새 방명록은 최신 작성순에 따라 첫 페이지에 추가되지만, 사용자가 다른 페이지를 보고 있었다면 현재 페이지에 머무릅니다.
-   방명록 페이지 이동 후에는 방명록 목록 위치로 자동 스크롤합니다.
-   페이지 번호는 현재 페이지 주변의 일부만 표시하고, 표시 범위 밖의 페이지는 `...`으로 생략합니다.
-   현재 페이지 번호는 배경색을 다르게 표시합니다.
-   첫 페이지의 `이전 페이지`와 마지막 페이지의 `다음 페이지` 버튼은 흐리게 표시하고 클릭할 수 없도록 비활성화합니다.
-   방명록 삭제 후에는 페이지 전체를 새로고침합니다.
-   방명록 수정 후에도 페이지 전체를 새로고침합니다.
-   방명록 삭제로 현재 페이지의 방명록이 하나도 남지 않으면 해당 페이지를 없애고 이전 페이지로 자동 이동합니다. 페이지 번호와 전체 페이지 수도 함께 갱신합니다.

```
F1 인증 ─┬─ F4 작품 ──────────────┐

```

#### 설계에 영향을 주는 핵심 관찰

1. **공통 모듈이 두 개 있습니다.** 드로잉 툴(F3)은 작품과 블록 디자인이, 아이소메트릭 엔진(F5)은 디자인 미리보기·편집기·관람이 함께 씁니다. 이 둘을 먼저 독립 모듈로 만들면 재작업이 크게 줄어듭니다.
2. **참조 관계가 많아 삭제 규칙이 가장 위험합니다.** 디자인 삭제 → 블록은 회색으로, 작품 삭제 → 액자는 빈 액자로, 블록 삭제 → 액자 동반 삭제, 전시 공간 삭제 → 하위 전부 삭제입니다. 이 규칙은 데이터 설계 단계에서 확정해야 합니다.
3. **관람은 "다른 사용자의 데이터"를 읽습니다.** 방문자는 소유자의 디자인과 작품 이미지를 보게 되므로, "다른 사용자의 디자인은 사용할 수 없다"는 규칙은 **관리·선택에만** 적용되고 **렌더링용 읽기는 공개**여야 합니다. 이미지 접근 방식도 이 점을 전제로 설계해야 합니다.
4. **블록 개수는 사실상 최대 1,200개입니다.** 20×20×3 칸에 칸당 블록 1개라서 "개수 제한 없음"과 충돌하지는 않습니다. 렌더링 성능 걱정은 크지 않습니다.
5. **좋아요순 정렬은 전체 전시 공간의 좋아요 수가 필요합니다.** 파일 기반 저장에서는 목록 조회 성능이 설계 이슈가 되므로 3·4장에서 다룹니다.

### 13.3 JSON 데이터 구조와 관계

#### 설계 원칙

- ID는 불투명한 값(`u_`, `g_`, `a_`, `d_`, `b_` + UUID)을 씁니다. 아이디(한글 포함)를 파일 경로에 쓰면 유니코드 정규화와 대소문자 문제가 생깁니다.
- 모든 JSON 파일 최상단에 `schemaVersion`을 둡니다.
- 시간은 ISO 문자열(UTC)로 저장합니다.
- 이미지는 JSON에 넣지 않고 파일로 저장하며, 경로는 ID 규칙으로 유도합니다. 파일 갱신 시 브라우저 캐시를 피하도록 `rev`(정수)를 올립니다.

#### 파일별 스키마

```jsonc
// data/users.json
{ "schemaVersion": 1, "users": [
  { "id": "u_…", "username": "모두", "usernameKey": "모두",   // key = NFC + 소문자 (중복 판정용)
    "passwordHash": "…", "createdAt": "…" } ] }

// data/users/{userId}/artworks.json
{ "artworks": [
  { "id": "a_…", "title": "노을", "titleKey": "노을", "description": "",
    "createdAt": "…", "updatedAt": "…", "rev": 1 } ] }

// data/users/{userId}/designs.json
{ "designs": [
  { "id": "d_…", "name": "벽돌", "nameKey": "벽돌",
    "createdAt": "…", "updatedAt": "…", "rev": 1 } ] }   // 면 이미지는 파일 3개

// data/galleries/{galleryId}/gallery.json
{ "id": "g_…", "ownerId": "u_…", "name": "…", "description": "",
  "cover": null,                    // 또는 "g_….jpg"
  "createdAt": "…",
  "blocks": [
    { "id": "b_…", "x": 3, "y": 7, "z": 0,       // x,y: 0~19 / z: 0~2
      "designId": null,                           // null = 기본 회색
      "frame": null }                             // 또는 { "artworkId": "a_…" | null }
  ] }                                              // artworkId null = 빈 액자

// data/galleries/{galleryId}/likes.json
{ "userIds": ["u_…"] }

// data/galleries/{galleryId}/guestbook.json
{ "entries": [
  { "id": "m_…", "authorId": "u_…", "content": "…",
    "createdAt": "…", "updatedAt": "…" } ] }       // 화면에는 createdAt의 날짜만 표시
```

#### 관계

```
User 1 ─ N Artwork        User 1 ─ N BlockDesign        User 1 ─ N Gallery (최대 5)
Gallery 1 ─ N Block (좌표 (x,y,z) 유일, 최대 1,200)
Block N ─ 0..1 BlockDesign   (designId, null = 회색)
Block 1 ─ 0..1 Frame         (블록에 내포)
Frame N ─ 0..1 Artwork       (artworkId, null = 빈 액자)
Gallery 1 ─ N GuestbookEntry (N ─ 1 User)
Gallery N ─ M User           (Like, 쌍 유일)
```

액자는 "블록 앞면당 1개"이고 블록과 생명주기가 같아서 블록 안에 내포했습니다. 작품과의 관계는 `artworkId` 참조로만 두어, 명세의 "작품 원본과 액자 연결을 분리" 요구를 충족합니다.

#### 삭제 시 처리 규칙

| 삭제 대상 | 함께 삭제 | 값만 변경 | 유지 |
|---|---|---|---|
| 전시 공간 | 블록, 액자, 방명록, 좋아요, 대표 이미지 파일(제안) | 없음 | 작품, 블록 디자인 |
| 블록 | 그 블록의 액자 | 없음 | 작품 파일, 디자인 |
| 액자 | 없음 | 없음 | 블록, 작품 |
| 작품 | 작품 레코드 + PNG 파일 | 이 작품을 참조하는 액자의 `artworkId` → null | 블록, 액자 |
| 블록 디자인 | 레코드 + 면 이미지 3개 | 이 디자인을 쓰던 블록의 `designId` → null | 블록 위치, 액자 |

- 작품과 디자인은 소유자만 쓸 수 있으므로, 참조를 정리할 범위는 **그 소유자의 전시 공간(최대 5개)** 으로 한정됩니다.
- 서버는 읽을 때도 "끊어진 참조는 회색 블록·빈 액자로 취급"하는 방어 로직을 둡니다. 삭제 중 장애가 나도 화면이 깨지지 않게 하기 위해서입니다.

#### 목록·정렬 성능

전시 공간이 폴더별로 흩어져 있어서 좋아요순 목록을 만들려면 전체를 읽어야 합니다. 서버 시작 시 전시 공간 요약(이름, 소유자, 좋아요 수, 생성일)을 **메모리 캐시**로 올리고, 변경 시 파일과 캐시를 함께 갱신하는 방식을 제안합니다. 서버가 단일 프로세스이고 세션도 메모리라는 전제와 맞습니다.

|---|---|---|
| 인증 | 가입 검증, 해시, 세션 발급·파기, `/me` | 오류 문구 표시, 상단 메뉴 전환 |
| 접근 제어 | 페이지·API 가드(페이지는 302, API는 401/403), 소유자 검사 | 401 응답 시 로그인 페이지로 이동하는 공통 처리 |
| 검증 | **모든 규칙의 최종 판정**(길이, 중복, 한도, 좌표 범위, 소유권) | 입력 중 즉시 피드백(글자 수 카운터 등). 보조 수단 |
| 저장 | JSON·이미지 입출력, 원자적 쓰기, 동시성 제어, 연쇄 삭제 | 없음 |
| 이미지 | PNG/JPG 시그니처·크기 검사, 파일 교체·삭제 | 캔버스에서 PNG 생성·업로드 |
| 드로잉 | 없음 | 펜·지우개·채우기·전체 지우기, 편집 중 상태(저장 전에는 서버 반영 없음) |
| 아이소메트릭 | 없음 | 투영·렌더링·키보드 선택 위치 처리, 텍스처 캐시, 미리보기 |
| 편집기 | 각 조작의 유효성(점유 칸, 층 범위, 참조 소유권) 검증 후 반영 | 모드 상태, 확인 창, 선택 중인 디자인·작품 |
| 목록·정렬 | 정렬(좋아요순 동률은 최신순), 페이지 분할 | 정렬 UI, 렌더링 |
| 좋아요 | 중복 방지, 개수 집계 | 버튼 상태 표시 |
| 방명록 | 작성자 권한 검사, 10개 단위 페이징, 마지막 페이지 보정 | 인라인 수정 UI, 글자 수, 페이지 번호 구성, 스크롤 |

#### API 윤곽 (경로명은 제안)

| 그룹 | 엔드포인트 |
|---|---|
| 인증 | `POST /api/auth/signup`, `login`, `logout` / `GET /api/auth/me` |
| 내 정보 | `GET /api/me` (아이디, 가입일, 전시 공간 수, 작품 수) |
| 작품 | `GET/POST /api/me/artworks`, `PATCH/DELETE /api/me/artworks/:id`, 이미지 교체 |
| 디자인 | `GET/POST /api/me/designs`, `PATCH/DELETE /api/me/designs/:id` |
| 전시 공간 | `GET /api/galleries?sort=&page=`, `GET /api/users/:username/galleries`, `GET /api/galleries/:id`(렌더링 묶음: 블록, 사용 디자인, 사용 작품, 좋아요 수, 내 좋아요 여부), `POST`, `PATCH`, `PUT cover`, `DELETE` |
| 블록·액자 | 기존 API 구조 조사 후 확정. 예: 블록 설치·수정·삭제 및 액자 설치·제거를 별도 작업으로 처리. 액자 교체는 제거 후 재설치 |
| 좋아요 | `PUT/DELETE …/like` (같은 요청을 반복해도 결과가 같게) |
| 방명록 | `GET …/guestbook?page=`, `POST`, `PATCH /:entryId`, `DELETE /:entryId` |

편집기 API는 갤러리 전체를 통째로 저장하는 방식이 아니라 **조작 단위**로 나눴습니다. 서버가 규칙을 조작마다 검증할 수 있고, 두 탭에서 편집해도 덮어쓰기 사고가 적습니다.

### 13.5 구현 순서

| 단계 | 내용 | 완료 확인 기준 |
|---|---|---|
| 0 | 미결정 사항 확정, 골격(Express, 세션, 설정 상수), 파일 저장소(원자적 쓰기, 뮤텍스), ID·문자열 유틸, 오류 응답 형식 | 서버 기동, 저장소 읽기·쓰기 동작 |
| 1 | 인증(가입·로그인·로그아웃·`/me`), 접근 가드, 상단 메뉴, `sign_in`, `main` 뼈대 | 모든 가입·로그인 오류 문구, 리다이렉트 규칙 |
| 2 | **드로잉 툴 모듈** + 작품 CRUD + `item_create` + `item_manage` | 생성·수정(이어 그리기)·삭제, 제목 중복 검사 |
| 3 | 전시 공간 CRUD + 대표 이미지 + `gallery_create` + 마이페이지(전시 공간·작품 관리, 통계) | 5개 한도, 이미지 검증, 삭제 확인 |
| 4 | **아이소메트릭 엔진** + `gallery_edit`(회색 블록부터): 층 선택, 방향키 선택 위치, `Enter` 설치·제거, 저장 버튼 | 20×20×3 범위 이동·설치·제거, 점유 칸 설치 차단, 저장 상태 확인 |
| 5 | 블록 디자인 CRUD + `design_edit`(면별 캔버스, 면 매핑, 저장 시 미리보기 갱신) + 편집기에서 새 블록용 디자인 선택 + 디자인 수정·삭제 시 참조 블록 처리 | 수정 시 사용 중인 모든 블록 반영, 삭제 시 회색 전환 |
| 6 | 액자 설치·제거, 작품 변경은 기존 액자 제거 후 재설치, 빈 액자, 작품 삭제 연쇄 | 작품 삭제 후 빈 액자 유지, 블록 제거 시 액자 동반 제거 |
| 7 | `gallery_view`(관람 전용), 전시 공간 목록·정렬(`main`, `gallery_list`, `gallery_user`) | 3종 정렬, 좋아요 동률 처리 |
| 8 | 좋아요 + 방명록(작성·인라인 수정·삭제·페이징·마지막 페이지 보정) | 비로그인 리다이렉트, 페이징 경계 케이스 |
| 9 | 전시 공간 삭제 연쇄, 오류 처리 점검, 고아 파일 정리, 반응형, 전체 시나리오 점검 | 명세 체크리스트 전 항목 통과 |

4단계(엔진)는 이 프로젝트에서 가장 위험한 부분이라, 디자인이나 액자 없이 회색 블록만으로 먼저 검증하도록 순서를 잡았습니다. 5·6단계는 그 위에 얹는 구조입니다.
